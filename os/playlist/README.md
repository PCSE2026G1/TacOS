# Playlist管理部品

## 機能

- Playlistの作成・破棄
- 曲の追加・削除・曲数とパスの取得
- ファイルへの新規保存・既存ファイルの更新保存
- ファイルからの読込み

## 保存形式と制限

- 1行につき1曲のパスを保存する．
- 改行コードはLF．CRLFは現在非対応．
- パスは最大255文字．
- ViewerのSaveは，読み込んだPlaylistと同じファイルへ保存する．
- 保存先が存在しない場合は新規作成し，存在する場合は内容を更新する．
- 保存内容と更新対象ファイルは，それぞれ最大32767バイトとする．
- 内容が短くなった場合，古い末尾を改行で埋める．読込み時は空行を無視する．
- ファイルサイズ自体は縮まらない．
- 保存失敗時はメモリ上の編集内容を保持するが，ディスク上の旧内容の保持は保証しない．
- 保存中の電源断に対する原子的な更新・復旧処理は未実装．
- 読込み成功時は，既存の内容を置き換える．
- 読込み失敗時は，元のPlaylistを保持する．
- 同じPlaylistを複数プロセスから同時操作する排他制御は未実装．

## テスト構成の注意

- tests/GNUmakefileは，既存のビルド済み部品を利用する．
- 共有部品のソースを自動で再ビルドする構成ではない．
- HomeStackTestAdapter.sは，Home接続テスト用の補助部品．
- PlaylistFault.sは原因調査用の診断部品で，現在の再生接続テストには結合しない．
- HomeStackTestAdapter.sは，現在のHome接続テストで引き続き使用する．
- これらを本番構成へ取り込むかは別途確認が必要．
- 現在のテスト入口は，PlaylistからMP3Playerへの再生接続を確認する．
- 以前の単体テストはHomePlaylistTest.cmmに残し，現在のテスト用カーネルには結合しない．
- PlaylistViewerを開くと，直接曲一覧を表示する．
- ボタン1は上，5は下，2は曲追加，3は選択曲削除，6は選択曲再生に割り当てる．
- ボタン4で終了確認を表示し，Save・Discard・Cancelを選択する．
- Saveは保存成功後にHomeへ戻る．保存失敗時は編集内容を保持して一覧へ戻る．
- Discardは保存せずHomeへ戻り，Cancelは編集を継続する．
- 一覧は拡張子付きのファイル名を最大14文字で表示する．
- 曲追加・曲削除はメモリ上へ反映する．SDカードへの保存はSaveを明示的に選択して行う．
- 曲の追加・削除後は一覧を再描画し，変更を直ちに表示する．
- 再生中のMP3Playerは別に曲情報を保持するため，編集対象からの削除だけでは再生を停止しない．
- 読込み元ファイルへの更新保存に対応する．保存先の選択は未実装．

## 現在のPlaylist再生接続テスト

### 前提

- TaC用ツールチェーン，CMake，Ninja，C/C++コンパイラが利用できること．
- 共有部品を先にビルドし，その後にPlaylistテスト用カーネルを生成する．
- commit済みソースを別ディレクトリへ展開し，共有MakefileやHomeの追加変更なしでビルドできることを確認済み．
- 再現ビルド版の最終実機確認は，以下の手順で行う．
- SDカードに，PLPLAY.TXTで指定したMP3ファイルが存在すること．
- このテストは実際の音と画面を確認して判定する．

### ビルド

リポジトリ直下から実行する．

```sh
(
  cd os || exit 1

  for dir in util kernel fs mm app file list audioDecoder clock mp3Player clockViewer; do
    make -C "$dir" EMBEDDED=1 DEBUG= CLOCKVIEWER_UNIT_TEST=0 || exit 1
  done

  make -C playlist/tests test-kernel || exit 1
  size-- playlist/tests/build/kernel0.o
)
```

共有部品のビルドでエラーが発生した場合は，先へ進まず原因を確認する．
Playlistテスト用カーネルはplaylist/tests/build/kernel0.binに生成される．
os/kernel0.binとは異なるため，転送するファイルを取り違えないこと．

通常の接続テストでは，MP3PLAYER_UNIT_TESTとCLOCKVIEWER_API_TESTを定義しない．
これらは各APIの単体テスト関数をコンパイルする場合だけ有効にする．
CLOCKVIEWER_UNIT_TESTとは別のマクロである．

初回のテストデータ配置には，次を使用する．
既存のPLPLAY.TXTを置き換えるため，必要な内容は事前に退避する．

```sh
cp playlist/tests/PLPLAY.TXT /Volumes/TACOS/PLPLAY.TXT
```

更新保存の確認中は，初期データをコピーし直さない．
HomePlaylistTest.cmm内の旧保存テストは現在無効化されており，更新保存の動作は実機操作で確認している．

### SDカードへのコピー

ビルド成功後に実行する．同名ファイルは置き換わるため，
事前にコピー先を確認する．
PLPLAY.TXTの配置は初回のみ行う．再配置すると保存済みの編集内容を置き換えるため，通常のカーネル転送ではコピーしない．

```sh
cp playlist/tests/build/kernel0.bin /Volumes/TACOS/KERNEL0.BIN
shasum playlist/tests/build/kernel0.bin /Volumes/TACOS/KERNEL0.BIN
sync
diskutil eject /Volumes/TACOS
```

### 実機での確認

1. HomeのPlaylistsを開き，直接曲一覧が表示されることを確認する．
2. ボタン1・5で移動し，ボタン6で選択曲を再生・停止できることを確認する．
3. 再生詳細画面から戻ると，一覧が正常に再描画されることを確認する．
4. ボタン2でFileChooserを開き，追加した曲が一覧に表示されることを確認する．
5. FileChooserをキャンセルしても，曲数が変わらないことを確認する．
6. ボタン3で選択曲だけが削除されることを確認する．
7. 全曲を削除し，空の状態でボタン3・6を押しても異常終了しないことを確認する．
8. 空の状態から曲を追加し，再生できることを確認する．
9. ボタン4からCancelを選び，編集内容を保持して一覧へ戻ることを確認する．
10. ボタン4からDiscardを選び，Homeへ戻ることを確認する．開き直すと保存元の内容になることを確認する．
11. PlaylistからShuffleを有効にして再生し，Homeへ戻っても自然終了後にPlaylist内の次曲へ進むことを確認する．
12. Now Playingの表示と，実際の再生曲が一致することを確認する．
13. ShuffleをOFF，RepeatをONにし，Homeでも自然終了後に同じ曲が再生されることを確認する．

### 更新保存の確認

このテストはPLPLAY.TXTを更新するため，必要な内容は事前にバックアップする．

1. 曲を追加してSaveし，Homeへ戻る．
2. 開き直し，追加した曲が残っていることを確認する．
3. 曲を削除してSaveし，開き直しても削除曲が復活しないことを確認する．
4. 全曲を削除してSaveし，開き直すと空になることを確認する．
5. 空の状態から1曲追加してSaveし，開き直して再生・停止できることを確認する．
6. Homeへ戻ってRESETし，最後に保存した曲が残っていることを確認する．
7. 保存中にはRESETや電源断を行わない．

Macでは次のコマンドで保存内容を確認できる．

```sh
cat /Volumes/TACOS/PLPLAY.TXT
od -An -tx1c /Volumes/TACOS/PLPLAY.TXT
```
曲を減らした場合は，末尾に空行が残る．
ファイルサイズや行数だけではなく，空行を除いたパスの内容と順序を確認する．

期待するログ：

操作時のログの一例：

```text
--- Playlist playback integration test ---
PL: added /MP3/MAOU_829.MP3
PL: saved/PLPLAY.TXT
PL: returned to Home
Playlist playback test: returned to Home
```

実際の曲名とログの順序は，行った操作により変わる．

- selected：再生する曲を決定したことを示す．
- returned to list：再生詳細画面から曲一覧へ戻ったことを示す．
- added：曲追加に成功したことを示す．
- removing：削除対象のフルパスを示す．
- removed：削除に成功したことを示す．
- 最後の2行：Playlist画面からHomeへ戻ったことを示す．
- save failed; keeping edits：保存に失敗し，編集内容を保持して一覧へ戻ったことを示す．直前のsavePlaylistのログで理由を確認する．
- saved/PLPLAY.TXT：読込み元のPlaylistへの保存に成功したことを示す．
